# 複数アカウント同時表示（Selected account icons）設計メモ — 日本語サマリー

英語版（upstream 提案用）: [selected-account-status-items-design.md](selected-account-status-items-design.md)

## やりたいこと
同じサービスの複数アカウント（例: ChatGPT/Codex ×2、Claude ×2）の「5時間枠」「週間枠」の使用率を、
メニューを開かず・アカウントを切り替えずに、メニューバーに並べて同時に見られるようにする。

## upstream の現状（2026-10-19 時点）
- **アカウントの取得はすでに対応済み**: Codex は管理アカウント／プロファイルホーム（CODEX_HOME 単位）、
  Claude は外部ツール claude-swap 連携（オプトイン・読み取り専用）、その他はトークンアカウント。
- **メニューの中では複数アカウントを並べて表示できる**（Stacked/Segmented、Overview の全アカウント表示）。
- **足りないのは「メニューバーにアカウントごとのアイコンを出す」部分だけ**。
  メンテナー（steipete）は方針を文書化済み（オプトイン・最大4つ・そのサービスのアイコンを置き換え・Merge Icons とは排他）。
- 過去に他の人の PR が2本（#3251, #3881）出たが、「保存済みレイアウトを無視する」「更新が無制限」「配置が保存されない」などの理由でクローズ。
  メンテナーは「メンテナー側で実装する」とも書いているので、**いきなり PR ではなく、まず Issue で「協力 PR を歓迎するか」を確認する**のが安全。

## 設計の要点
- 新しいデータ取得は**一切追加しない**。表示層だけ。既存のアカウント情報を共通の形に揃えてアイコンを描く。
- 設定: サービスごとに「1つのアイコン（今まで通り）」/「選んだアカウントのアイコン（最大4つ）」。
- アイコンのラベルはユーザーが付けた別名か「Account 1/2…」。メールアドレスは絶対に出さない。
- 描画は既存のレイアウト描画エンジンをそのまま使う（過去 PR が却下された原因を回避）。
- 更新は既存の更新スケジュールの中で、選んだアカウントを優先するだけ（上限6件のまま。オフなら今と完全に同じ）。
- 設定は新しいキーに保存し、古いバージョンに戻しても壊れない。

## データ取得元の判断（規約の観点）
- **Codex**: アカウントごとに CODEX_HOME を分け、公式の `codex app-server`（`account/rateLimits/read`）を使う「CLI」ソースを推奨。公式経路なので規約上もっとも安全。
- **Claude**: upstream で複数アカウントを扱える経路は claude-swap だけで、claude-swap も内部で非公式の
  `api.anthropic.com/api/oauth/usage` を呼んでいる（CodexBar 本体の OAuth ソースも同じ）。Anthropic の規約上グレー。
  公式に文書化された経路は Claude Code の statusLine JSON（`rate_limits.five_hour / seven_day`）で、
  CLAUDE_CONFIG_DIR を分ければアカウントごとに取れる。ただしメンテナーが一度採用して**取り消した**（#3006：
  アカウント情報がなく、Claude Code を使っている間しか更新されない割に保守コストが大きい）。
  → **upstream 提案では蒸し返さない**。今回の表示層はデータ元に依存しないので、将来ちゃんとした経路ができればそのまま使える。
  → 萩野さん個人用としては、(a) claude-swap を使う（グレーを許容）、(b) フォーク側だけで statusLine 経由の取得を後から足す、のどちらかを選ぶ形。
- **Grok**: 1アカウントなので今回の対象外（既存表示のまま）。**Genspark**: 規約で自動収集禁止のため対象外。
