## 2. Provider icon/text rendering and its inputs

Current flow:

```text
UsageStore.menuBarSnapshot(provider instance)
  → StatusItemController.applyIcon(provider, phase, item, merged)
    → stored layout, when applicable
      → UsageStore.menuBarLayoutRenderData(provider, snapshot, ...)
      → MenuBarLayoutRenderer.render(layout, data, icon, options)
      → applyMenuBarLayoutContent(rendered, button, gap)
    → otherwise legacy brand+text or IconRenderer meter/critter path
```

- `Sources/CodexBar/UsageStore.swift:668`, `menuBarSnapshot(for:)`: Claude adapter active-account override, else ordinary provider snapshot. `Providers/Claude/UsageStore+ClaudeSwapRefresh.swift:41` admits the active adapter snapshot only when adapter presentation wins and `usesLastKnownUsage == false`; otherwise today's **provider** icon falls back to ambient data.
- `Sources/CodexBar/StatusItemController+Animation.swift:333`, private `applyIcon`: reads the provider snapshot itself (:349), settings/style, warning, stale/animation state; attempts stored layout (:363); otherwise brand+display text, then legacy meter/critter/credits rendering. Public `applyIcon(for:phase:)` (:327) addresses the provider dictionary. It is not yet a renderer accepting an account snapshot/item identity.
- `Sources/CodexBar/StatusItemController+MenuBarLayout.swift:37`, `applyStoredMenuBarLayoutIfNeeded`: accepts **provider + `UsageSnapshot?` + icon + warning + target `NSStatusItem` + time**. Applies only to nonlegacy resolution with `.iconAndPercent`. Passes resolved data/options to renderer and applies title/image/width; currently invalidates provider-keyed render cache.
- Same file:200, `menuBarLayoutRenderData`, delegates to `UsageStore.menuBarLayoutRenderData` (:329). `menuBarLayoutWindows` (:444) produces primary/secondary/tertiary/session/weekly/automatic/spend windows; Codex goes through its consumer projection, others through semantic window and metric resolvers.
- `Sources/CodexBar/MenuBarMetricWindowResolver.swift:5`, `rateWindow`: accepts preference, provider, optional snapshot, average support, Antigravity policy and time. Descriptor presentation can resolve a window or provide Auto candidates; generic fallback supports explicit lanes, most-constrained primary/secondary, average, spend, and Auto. Auto uses Core `AutomaticQuotaSelection`; provider semantics matter, not just `snapshot.primary`.
- `Sources/CodexBar/MenuBarLayoutRenderer.swift:60`, `MenuBarLayoutRenderData`: already resolved, hashable provider/name/account label, window values and labels, optional extras, pace/runs-out, balances, throughput/sparkline, costs, spend and numeric conditional metrics. Renderer receives **no `UsageSnapshot` directly**. `MenuBarLayoutRenderOptions` (:138) supplies size, contrast, used/remaining, conditional library, appearance, stale/highlight, time, color and typography. `MenuBarLayoutRenderer.render` (:323) returns `MenuBarLayoutRenderedTitle` (:239): attributed title/leading icon or template status image, accessibility label, width. It is AppKit code.
- `StatusItemController+MenuBarLayout.swift:287`, `applyMenuBarLayoutContent`, sets title/image/position/accessibility and returns explicit item width. A two-line layout can lift one leading icon beside both rows.

Saved custom layouts:

- `Sources/CodexBar/MenuBarLayout.swift:514`, `MenuBarLayoutToken`; :803, Codable `MenuBarLayout` with normalized lines; :960, `MenuBarLayoutResolution` (stored vs legacy/migrated); :1051, `MenuBarLayoutPersistence`.
- `MenuBarLayout.swift:875`, `MenuBarLayoutUserDefaultsKey`: global, provider overrides and conditional libraries with legacy/released/V3/V4/V5/current **V6** keys. Compatibility projections and comparison against older generations retain richer layouts unless an older app actually edited its compatible projection.
- `Sources/CodexBar/SettingsStore.swift:863`, :875, :904 load layout/conditionals/overrides. `SettingsStore+Defaults.swift:444`, `menuBarLayoutResolution(for:)`: provider override → global stored layout → legacy resolution. `setMenuBarLayout` (:458) and persistence helpers (:502, :512, :524) write compatible generations. Layout/geometry is local, not CloudKit configuration.

**Account renderer reuse constraint:** passing a different snapshot is necessary but insufficient. Current options derive stale state from the provider (:177); costs come from the current provider configuration (:235); pace/history, spend and Codex credits projections also use store context. An account item must receive account-owned optional extras/history/credits/errors or omit them. Never fall back to the active account's data for an unavailable selected account. Cache, animation, highlight and countdown bookkeeping must include item identity; `iconKey` cannot remain only `provider:warning` when account data differs.

### Scheduling and bounds; non-active Codex answer

1. `UsageStore.swift:921`, `startTimer`: Manual disables the recurring timer; fixed cadence uses `effectiveAutomaticRefreshInterval` (including low-power behavior), adaptive cadence recomputes sleep before each tick. Both call `refresh(enrichmentMode: .automatic)`. `UsageStore+RefreshEnrichment.swift:50` → `UsageStore.swift:762`, `runRefresh`, guards overlap and dispatches background-enabled providers. Startup, manual and menu/settings refreshes are separate entry paths.
2. `Sources/CodexBar/UsageStore+Refresh.swift:101`, `refreshProvider`, coordinates requests/generations; `refreshProviderPass` (:291) chooses fan-out before ordinary single-account fetching. Codex IDs explicitly requested or `shouldFetchAllCodexVisibleAccounts()` trigger fan-out (:312); Claude schedules its independent list task (:332); token fan-out is :336.
3. `Sources/CodexBar/UsageStore+AccountRefreshPolicy.swift:4`: **six** accounts per ordinary fan-out. `shouldFetchAllTokenAccounts` (:15) requires supported provider + effective selected token and either account widgets with accounts or stacked account menus with >1 account. `shouldFetchAllCodexVisibleAccounts` (:22) requires >1 visible account and stacked account menus **or** account widgets, and rejects ambient PAT mode (PAT is not a per-visible-account credential).
4. Therefore **yes, a non-active Codex account can refresh periodically**, when those fan-out conditions hold and its row is admitted to the six-account batch. In segmented mode with widgets off, ordinary ticks refresh the followed account; siblings retain cached readings and need explicit refresh/selection. There is no separate unconditional non-active-account polling loop. Manual frequency, disabled provider, PAT mode and the six-row cap limit this further. More than six accounts do not imply fair rotation: `limitedCodexVisibleAccounts` uses presentation ordering then a prefix, ensuring active inclusion, not round-robin.
5. `UsageStore+TokenAccounts.swift:624`, `limitedTokenAccounts`, takes first six while ensuring selected account inclusion; :640, `limitedCodexVisibleAccounts`, orders through `CodexAccountPresentationOrdering` and likewise ensures active inclusion. `fetchTokenAccountOutcomes` (:685) either serializes with the catalog's minimum account delay or uses a task group; Codex `fetchCodexVisibleAccountOutcomes` (:760) uses a task group. Count is bounded before task creation (up to six); these are not a shared global network concurrency limiter. Provider fetch strategies retain their own timeouts/retry/confirmation policies.
6. Settings `Providers/Codex/UsageStore+CodexAccountUsageOverview.swift:67`, `refreshCodexAccountsForSettings`, visits explicit requested IDs in batches of six without changing followed selection; each batch uses `refreshProvider(...codexAccountIDs:)`. Opening Settings only reads retained data.
7. Claude `UsageStore+ClaudeSwapRefresh.swift:80`, `scheduleClaudeSwapAccountRefresh`, cancels/replaces its prior list task and runs independently of ambient fetch. Gate (:26): provider enabled, adapter enabled, nonempty executable. `ClaudeSwapAccountReader.swift:25` has 262,144-byte output bound and 30-second list timeout; `readAccountList` (:29) executes fixed source arguments, no shell. It reads the tool's complete cached list, not one subprocess per selected account. `isCurrentClaudeSwapRefresh` (:282) prevents obsolete publication. A source version probe is separately bounded. Explicit switching (:181) is serialized and deliberately allowed to finish its external credential transaction; that is not the polling timeout contract.

`UsageStore+TokenRefreshSequence.swift` schedules **local token/cost scans**, not saved-token quota fan-out. Do not confuse that cost sequence with `refreshTokenAccounts` above.

## 7. Minimal implementation proposal (not current behavior)

Preserve accepted product scope: per-provider opt-in **One provider icon / Selected account icons**, ordered selection of at most four accounts; replace that provider's item; preserve other provider items. Merge Icons remains one item and is mutually exclusive with account mode. Controls disabled while the **saved** Merge Icons setting is on, with explicit “Turn Merge Icons off”; do not exploit the one-provider effective-merge exception. Keep saved account choices while merge is on so turning it off can restore intent. No automatic credential switching.

### Core policy to add

Add **`Sources/CodexBarCore/SelectedAccountIcons.swift`** (proposed), containing Codable versioned selection records, a provider/source/opaque-ID key, normalization (dedupe/order/cap four), pure effective-item planning and privacy badge policy. `StatusItemIdentity.account(provider:source:opaqueID:)` should use this key; the AppKit controller can retain its nested wrapper or delegate to a Core identity type. Avoid moving the whole app renderer/layout subsystem to Core for this feature.

Source-owned identity conversion must be explicit:

- Claude: source `claude-swap` or `tcr`, opaque numeric slot (existing `ProviderAccountIdentity`).
- Tokens: source `token-account`, opaque persisted UUID; never token/hash-of-token or label.
- Managed Codex: source `codex-managed`, opaque managed UUID, with workspace ownership checked on lookup. Do not reuse email-based visible ID.
- Profile/system Codex: need a machine-local opaque identifier registry for normalized home/source identity, not plaintext paths or emails in autosave names. Define whether a system slot follows the changing system credential; safest account semantics require inventory identity validation and suspension when its owner changes. If that cannot be guaranteed minimally, initially expose only managed UUID accounts for Codex selection and explain profile/system ineligibility in UI. Do not claim existing visible IDs solve this.

Use an unambiguous encoding or deterministic namespaced digest of the opaque tuple for new autosave/accessibility names. Retain existing merged/provider autosave names byte-for-byte. Never include email, alias, raw path or credential-derived material. Alias/ordinal is display only; use a bounded user-chosen alias when permitted, and `Account N` under Hide Personal Info. Stable ordinal derives from persisted selection order, not current usage ranking; never truncate email into a badge. Alias itself may contain personal text, so privacy mode must override it in tooltips/accessibility too.

### Refresh and persistence contracts to pin before implementation

- No new per-item polling timer. Selected icons add account demand to provider ticks; coalesce within existing provider coordinator. At most four selected accounts + followed account fit within six. If widget/stacked demand exceeds remaining capacity, explicitly define admission/fairness rather than silently starving a selected icon. Respect Manual, disabled providers, source-specific pacing and PAT exclusions. Claude continues one bounded list read, not four subprocesses.
- On account removal/source change, retain saved intent but suspend unavailable selections; show unavailable state or fall back to one provider icon when no selected account resolves. State this zero-selection behavior in UI/tests. Do not borrow another account's snapshot or delete choices merely because one fetch failed. Never render source-declared last-known measurements as live age-less quota; show unavailable/stale affordance instead.
- Keep current provider layouts, provider autosave positions, `mergeIcons` and source choices intact except for an explicit user action. New local defaults key (for example `selectedAccountIconsV1`) is additive; older apps ignore it and continue their provider items. A downgrade must not decode/rewrite the new payload through `config.json` normalization. Returning to the new app restores selection, subject to current availability and merge intent. Unknown future versions stay untouched/read-only with safe provider-item fallback. Test malformed data, future versions, downgrade/upgrade preservation, and old-app merge edits.
- No aliases/emails in autosave/defaults logs. If storing a user alias is required, treat it as local personal display data, never identity; otherwise persist only opaque selections and derive source-provided alias at runtime. New settings are not automatically included in portable preferences or iCloud sync.
